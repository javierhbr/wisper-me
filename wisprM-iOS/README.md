# wisprM for iPhone

A native SwiftUI app with on-device Whisper and Parakeet transcription, local formatting, optional language-model polishing, clipboard copying, private history, and an original custom keyboard for inserting completed transcripts.

The Mac app remains in the parent directory. This project shares our own `WisprCore` formatting and privacy code; it does not use any Wispr Flow files or assets.

## Requirements

- Xcode 26 or newer with the iOS SDK and an iPhone simulator installed.
- iOS 17 or newer for the application. Actual model performance depends on device memory and chip.
- An Apple development team for signing on a real phone. The keyboard sharing feature uses an App Group, which must be available for the chosen team and provisioned on both targets.
- Internet access for the initial Swift package resolution and each model's first download. Speech runs on-device after the model and tokenizer have been cached.

MLX also needs Apple's optional Metal compiler component. Install it once if Xcode reports a missing Metal Toolchain:

```sh
xcodebuild -downloadComponent MetalToolchain
```

The CLI build uses the pinned, inspected MLX build plugin in noninteractive mode and sets `SPM_CUDA=0` for Apple platforms. FluidAudio's unused NeMo text-normalization engine is disabled through its supported package trait; speech recognition remains enabled. Complete Xcode logs are retained under `.build/`.

## Build and run

From this directory:

```sh
make build               # Simulator app and embedded keyboard
make test                # Mobile shared-domain tests
make device              # Unsigned arm64 iPhone Release build
open wisprM.xcodeproj    # Sign and run on a physical iPhone
```

The project is generated by `scripts/generate-project.py`; no XcodeGen, CocoaPods, Python runtime, or model server is required for speech recognition. The generator updates source membership deterministically. `make build` regenerates it automatically.

The simulator app is `.build/DerivedData/Build/Products/Debug-iphonesimulator/wisprM.app`. The device build is `.build/Device/Build/Products/Release-iphoneos/wisprM.app`.

To launch a simulator:

```sh
xcrun simctl list devices available
make run SIMULATOR_ID=<device-uuid>
```

Simulator speech processing is useful for functional checks, but it does not establish iPhone speed, memory, battery use, or microphone behavior. The pinned MLX runtime requires Metal shared-memory heaps unavailable in Simulator. On-device LLM preparation is therefore rejected safely in Simulator; use a physical iPhone for that feature. Whisper, Parakeet, deterministic formatting, and the optional server client remain available in Simulator.

## Install on an iPhone

1. Copy `signing.example.json` to `signing.local.json`. Set your team ID, a unique bundle identifier, and an App Group registered to that team. This local file is ignored by Git.
2. Run `make project`, open `wisprM.xcodeproj`, connect the phone, and select it as the run destination.
3. In Signing & Capabilities, ensure the App Group is enabled for both **wisprM** and **WisprKeyboard**. Both targets use the group from your local JSON configuration. No Swift source edits are needed.
4. Run the **wisprM** scheme. Approve the iPhone's normal Developer Mode/trust steps when requested by Xcode or the phone.

Project regeneration preserves signing from `signing.local.json`. Direct edits to the generated project can be overwritten, so keep team/identifier settings in that file. `make project TEAM=YOURTEAMID` can override just the team for that generation.

Unsigned device output cannot be installed on a phone until it is signed and provisioned. The application does not bypass Apple's signing or microphone permission requirements.

## Dictate and paste

1. In **Models**, select Whisper Tiny, Base, Small, or **Parakeet TDT 0.6B v3**.
2. Tap **Download & load speech model** once. The selected model is remembered and automatically loaded from cached files when the app opens again. The first download can be large; model loading can also take time as iOS prepares Core ML caches.
3. In **Dictate**, tap **Start dictation**, grant microphone permission, speak, then tap **Finish dictation**.
4. Finished text is copied to the system clipboard while wisprM is active. Paste it in your destination app, or use **Copy** and the Share button.

If processing finishes in the background, return to wisprM to trigger the clipboard copy. A background result can also be read by the keyboard when App Group sharing is provisioned. Recording is capped at three minutes. Audio-file imports are limited to 100 MB and ten minutes; format support is supplied by native AVFoundation, not the Mac's FFmpeg runtime.

Phone calls and other audio interruptions end recording and process the captured portion where possible. Temporary audio is deleted after completion/cancellation; stale owned recordings are cleaned on launch. Importing audio makes a temporary private copy and never deletes the original.

The Shortcuts app exposes **Open wisprM Dictation**. It can be assigned to supported Action buttons. This opens the app; it does not silently activate the microphone or provide a global desktop shortcut.

## Use the keyboard

1. Add **wisprM** in iPhone Settings → General → Keyboard → Keyboards → Add New Keyboard.
2. Record and finish a dictation in the main app.
3. Return to a destination text field and select wisprM using the globe key.
4. Tap **Refresh**, then **Insert latest transcript**.

The keyboard reads the latest shared result, shows a preview, and inserts only on an explicit tap. The insertion window expires after ten minutes; stale shared files are removed when the main app next becomes active. Shared files are excluded from backups and can be cleared in Settings. A result cannot be inserted repeatedly under the same transcript ID. Basic typing, shift, space, delete, return, and switching keyboards work without network access. The keyboard requests no Full Access and performs no network requests.

iOS prohibits keyboard extensions from accessing the microphone. This version uses the main-app recording flow; it does not pretend the keyboard can record or wake a suspended app. Secure text fields and some applications require the system keyboard. Clipboard paste remains the fallback. If sharing is not provisioned, the main app displays the limitation in Settings.

## Models and storage

Your speech-model selection persists across app restarts. Startup restores complete cached weights without permitting a model download. Cached preset files can also be recovered if their installation receipt is missing; incomplete or deleted models still require an explicit download in Models. After polishing or manually unloading models, **Start dictation** reloads the selected cached model automatically.

- **Whisper:** native WhisperKit, pinned SDK 1.1.1, using the explicit `openai_whisper-tiny`, `openai_whisper-base`, and `openai_whisper-small` Core ML variants.
- **Parakeet:** native FluidAudio, pinned SDK 0.17.7, explicitly `.v3` with the int8 encoder. This is the multilingual **TDT 0.6B v3** model, not v2.
- iOS assets differ from the Mac MLX files. The UI reports the actual installed model folder size and location after downloading; Mac download figures are not reused.
- Models can be unloaded to release memory or deleted and downloaded again. Model assets are excluded from backup where managed by the app. The SDKs maintain some additional tokenizer/compiled caches.
- Downloaded model revisions are managed by the pinned SDKs' repositories; their weight files are not currently locked to an immutable Hub revision. `Package.resolved` records Swift dependency revisions.

**Compatible custom models:** use a WhisperKit repository ID and its exact variant folder name, or import a complete model folder from Files. Select Whisper or Parakeet before importing a speech folder. Whisper requires WhisperKit Core ML components; Parakeet requires the v3 compiled components and vocabulary, including `JointDecisionv3.mlmodelc`. The app copies imported files into private storage, rejects symbolic links, and validates compatibility when loading. Models in Mac MLX speech formats are not interchangeable with these native formats.

The Models screen also provides **Delete all downloaded model files** to reclaim partial or failed downloads. This deletes only the app-managed model directory, including imported and text models; history is unaffected.

The first download uses the network. Recognition does not upload audio or transcripts. No model weights are included in the source repository.

## Optional polishing

**Local cleanup only** is the default and uses the shared deterministic formatter.

**Apple Intelligence** uses Apple's on-device Foundation Models framework on compatible iPhones running iOS 26 or later. In **Models → Optional text polishing**, choose **Apple Intelligence**. The screen shows whether the device is eligible, Apple Intelligence is enabled, the system model is ready, and the selected language is supported. Use **Check availability** after changing system settings; availability also refreshes when wisprM returns to the foreground.

The app sends only the completed transcript to the on-device system model, with instructions to correct grammar, punctuation, spelling, and capitalization while preserving language, meaning, names, numbers, and structure. No cloud provider or separate app-managed LLM download is used. Keep wisprM open while polishing. Unavailable models, unsupported languages, oversized input, generation errors, and provider changes preserve local cleanup. This option accepts up to 6,000 UTF-8 bytes per transcript; the framework also enforces its actual context limit. Apple's operating system manages its own model storage. App-managed speech/text models are unloaded before the request to reduce memory use, and the cached speech model automatically loads when the next recording starts.

**On-device language model** uses native MLX Swift LM 2.31.3. Enter a compatible Hugging Face MLX model ID, such as the default small Qwen2.5 0.5B 4-bit model, or import a complete MLX model/tokenizer folder from Files. Architectures and tokenizers must be supported by that SDK; arbitrary model files are not executable plugins. Download the text weights in Models. The selected cached speech model loads automatically when dictation starts. For memory conservation, speech weights are unloaded before local polishing, and the text model is unloaded afterwards, including on cancellation. The cached speech model automatically reloads before the next recording. Device memory may limit usable models. Keep the app open during MLX polishing; if it becomes inactive, the app cancels polishing and preserves local cleanup.

**Model server** uses a compatible HTTPS chat-completions endpoint and an explicit model name. Save an optional API key in Keychain; it is scoped to the endpoint origin. Transcript text is sent to that server only while this mode remains selected. Audio remains on the phone. `localhost` refers to the phone, not a Mac running Ollama. Do not disable TLS to reach a Mac; expose a trusted HTTPS endpoint if you choose this mode.

If polishing is disabled during a pending request, the result is discarded and local cleanup is retained. Failed polishing also preserves the recognized text. History is off by default; enabling it keeps at most 30 transcripts. Disabling history deletes saved history. Shared keyboard results can be cleared separately.

## Verification

```sh
make test
python3 scripts/integration-transcription.py --model whisper-tiny
python3 scripts/integration-transcription.py --model parakeet-v3
python3 scripts/integration-relaunch.py --model parakeet-v3
python3 scripts/integration-relaunch.py --model whisper-tiny
```

The integration script generates a speech fixture with macOS speech synthesis, runs the app's real model/decoder/formatting pipeline in Simulator, and saves a JSON report in `.build/`. Its developer route is compiled only into Debug builds and does not write to the clipboard during the test. It never records the microphone or reads personal audio. App/console processes are cleaned up on success and failure. The `--polish-model` option exercises the expected safe Simulator rejection and preserved local result; it cannot establish physical-phone MLX behavior. See [VERIFICATION.md](VERIFICATION.md) for the checks actually completed and their limits.

### Generated-speech test on a physical iPhone

Build and install a signed **Debug** app first using the iPhone instructions above. Find its CoreDevice identifier with `xcrun devicectl list devices`, then run:

```sh
python3 scripts/integration-phone.py --device <coredevice-id> --model whisper-tiny
python3 scripts/integration-phone.py --device <coredevice-id> --model parakeet-v3
python3 scripts/integration-phone.py --device <coredevice-id> --model whisper-tiny --polish-model mlx-community/Qwen2.5-0.5B-Instruct-4bit
python3 scripts/integration-phone.py --device <coredevice-id> --model whisper-tiny --apple-intelligence --phrase "She go to the store yesterday and buy two apple."
```

The default app path is `.build/Phone/Build/Products/Debug-iphoneos/wisprM.app`; pass `--app` if your signed Debug build is elsewhere. Keep the phone unlocked and wisprM in the foreground. The script copies generated speech into this app's Documents folder, launches the real inference pipeline, and retrieves only its JSON report into `.build/phone-*.json`. It neither captures the microphone nor writes the clipboard. Fixture preferences, history, and shared transcripts are isolated from normal use; model weights are reused. Polishing reports include the provider, completion status, and text before and after editing; a preserved transcript alone does not count as successful polishing. Both integration scripts accept `--apple-intelligence`, `--phrase`, and `--language`; `--polish-model` and `--apple-intelligence` are mutually exclusive. Microphone capture, clipboard paste, and keyboard insertion require separate interactive checks.
